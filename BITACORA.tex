\section*{2026-06-13 — AVM (M2 Valuación) + Oportunidades (M5) en Streamlit}
\addcontentsline{toc}{section}{2026-06-13 — AVM + Oportunidades}

\subsection*{Qué se hizo}
\begin{itemize}
  \item \codigo{src/valuacion/avm.py}: modelo de valuación automática que estima el
        precio de venta por características (m², recámaras, baños) + ubicación
        (municipio, colonia) + tipo. Target \codigo{log(precio)}.
  \item Compara 3 modelos en \textbf{train / validation / test} (60/20/20):
        \textbf{Gradient Boosting} (ML) + clásicos \textbf{Random Forest} y
        \textbf{Ridge}. Métricas: MAE, RMSE, R², MAPE, \textbf{MdAPE}.
  \item Valor estimado \textbf{out-of-fold} (cada inmueble valuado por un modelo que
        no lo vio) → \codigo{subvaluacion\_pct = (estimado - precio)/estimado}.
  \item Visor con \textbf{pestañas}: 🗺️ Mapa · 🤖 Modelo (métricas/performance,
        scatter estimado-vs-real, importancia de variables) · 💎 Oportunidades.
  \item Dependencia: \codigo{scikit-learn}.
\end{itemize}

\subsection*{Resultados (snapshot, 9{,}432 inmuebles venta)}
\begin{itemize}
  \item Gradient Boosting / Random Forest: \textbf{MdAPE $\sim$21\%}, R² $\sim$0.55.
  \item Ridge (lineal): MdAPE 26\%, R² 0.06 — el clásico lineal queda muy por
        debajo (real estate es no-lineal). Mejor: Random Forest.
  \item v1 con margen de mejora (la meta del plan era MdAPE $\sim$11\%): faltan
        coords finas, antigüedad, amenidades, modelar \$/m².
\end{itemize}

\subsection*{Oportunidades · Benito Juárez (M5)}
\begin{itemize}
  \item 20 casas/deptos pedidas; salen \textbf{19 creíbles} (<3 MDP, subvaluación
        15–45\%).
  \item \textbf{Hallazgo de honestidad}: la subvaluación $>$45\% en zona cara
        resultó ser \textbf{error de dato} (p.ej. casa de 184 m² en Nápoles a
        \$600k). Se acotó a la banda 15–45\% → las oportunidades quedan reales,
        no listings con precio mal capturado. Esto ES el producto: decir cuándo
        algo es ``demasiado bueno para ser verdad''.
\end{itemize}

\subsection*{Pendiente / siguiente}
\begin{itemize}
  \pend Mejorar el AVM: \$/m² como target, coords, antigüedad, amenidades; bajar MdAPE.
  \pend Geocodificar Inmuebles24 al terminar su scrape.
\end{itemize}

\section*{2026-06-13 — Deduplicación (Etapa 10): un inmueble, el más barato}
\addcontentsline{toc}{section}{2026-06-13 — Deduplicación}

\subsection*{Qué se hizo}
\begin{itemize}
  \item \codigo{src/ingesta/dedup.py}: une todos los CSVs, detecta el mismo
        inmueble publicado repetido (varios brokers / varios portales) y colapsa
        cada grupo a UN registro = \textbf{el más barato}.
  \item \textbf{Firma}: (municipio, colonia, tipo, operación, m² en bucket,
        recámaras, baños), normalizando texto (sin acentos/mayúsculas) para casar
        entre portales.
  \item \textbf{Control de precio}: dentro de cada firma, dos anuncios solo son el
        mismo inmueble si su precio está dentro de $\pm$\codigo{tol} (def 30\%).
        Evita fusionar inmuebles distintos de la misma colonia/m² (p.ej. un
        \$2.3M con un \$26M). Parámetros: \codigo{--tol}, \codigo{--m2-bucket},
        \codigo{--scope global|intra}.
  \item Salida \codigo{data/processed/\_unificado\_dedup.csv} con
        \codigo{n\_anuncios}, \codigo{portales}, \codigo{precio\_min/max},
        \codigo{ahorro}.
\end{itemize}

\subsection*{Resultado (snapshot durante la corrida)}
\begin{itemize}
  \item $\sim$16.6k anuncios crudos $\to$ $\sim$12.9k inmuebles únicos
        (\textbf{22\% duplicados} eliminados).
  \item $\sim$460 duplicados \textbf{multi-portal} (mismo inmueble en varios sitios).
  \item Se valida con spot-check: los matches multi-portal tienen spreads de precio
        creíbles ($\pm$30\%); se corrigió un over-merge inicial (firma sin precio).
\end{itemize}

\subsection*{Pendiente / siguiente}

\section*{2026-06-13 — Inmuebles24 vía CloakBrowser + geocoding por colonia}
\addcontentsline{toc}{section}{2026-06-13 — Inmuebles24 (CloakBrowser) + geocode}

\subsection*{Decisión}
Se agotaron los portales fáciles con coordenadas (CyT + Lamudi). Pincali no trae
coords (es EasyBroker por debajo); iCasas las tiene pero su HTML es frágil. Se
decidió ir por los 3 grandes (mayor inventario) con la técnica \textbf{CloakBrowser}
del repo FotMob — Nivel B, decisión consciente del dueño pese al ``no evadir'' del
catálogo. Se empezó por \textbf{Inmuebles24}.

\subsection*{Qué se hizo}
\begin{itemize}
  \item \codigo{src/ingesta/browser.py}: sesión CloakBrowser (warmup resuelve
        Cloudflare una vez, reutiliza la sesión). Confirmado: pasa el Cloudflare
        de Inmuebles24 (título real ``4,849 Departamentos…'').
  \item \codigo{src/ingesta/inmuebles24.py}: scraper que parsea las tarjetas
        \codigo{posting} con \textbf{BeautifulSoup} (id, precio, dirección,
        colonia/alcaldía, m²/rec/baños/estac, URL, tipo PROPERTY/DEVELOPMENT);
        pagina con \codigo{-pagina-N.html}; dedup por id; JSONL + CSV; reanudable.
  \item \codigo{src/ingesta/geocode.py}: \textbf{geocodificación por colonia} vía
        OSM/Nominatim (1 req/s, User-Agent identificable, viewbox ZMVM, caché en
        \codigo{data/geocode\_cache.json}). Reutilizable para cualquier portal sin
        coords.
  \item Dependencias: \codigo{cloakbrowser}, \codigo{beautifulsoup4}.
\end{itemize}

\subsection*{Prueba (pipeline completo)}
\begin{itemize}
  \item Scrape BJ deptos venta (2 pág): 51 postings, todos con precio/colonia/m².
        Paginación OK.
  \item Geocode: 27 colonias únicas → \textbf{50/51 filas con coordenadas} a nivel
        colonia, cacheadas.
\end{itemize}

\subsection*{Caveats}
\begin{itemize}
  \item Inmuebles24 \textbf{no expone coordenadas} → posición a nivel colonia
        (aproximada), no exacta.
  \item Tarjetas \codigo{DEVELOPMENT} (preventa) traen precios/m² en rango; se
        marcan con \codigo{card\_type} para poder filtrarlas.
  \item El scrape es por navegador → lento (horas para CDMX+ZMVM completo). Reanudable.
\end{itemize}

\begin{itemize}

\subsection*{PoC — Casas y Terrenos (Nivel A)}
\begin{itemize}
  \item \codigo{robots.txt} permite los listados para \codigo{User-Agent: *}
        (solo bloquea \codigo{/api/}, \codigo{/beta/} y bots SEO). Sin anti-bot.
  \item Next.js: los listados vienen en \codigo{\_\_NEXT\_DATA\_\_} →
        \codigo{props.pageProps.initialState.propertyData.properties}.
        URL \codigo{/\{estado\}/\{municipio\}/\{tipo\}/\{operacion\}?page=N}
        (240/pág, 1-indexed); total en \codigo{estimatedTotalHits}.
  \item Se construyó \codigo{src/ingesta/casasyterrenos.py} (config-driven desde
        \codigo{config.yml}): itera alcaldías CDMX + municipios ZMVM × tipos ×
        operaciones, pagina, filtra por \codigo{lastUpdate} (3 meses), deduplica
        por \codigo{id}, guarda JSONL (raw) + CSV (plano). Reanudable.
  \item Dependencias de la etapa: \codigo{requests}, \codigo{PyYAML}
        (instaladas en \codigo{cimenta\_env}).
  \item \textbf{Prueba (Benito Juárez, 14 combos, $\sim$45 s): 855 propiedades
        únicas $\leq$3 meses}, dedup perfecto (855 CSV = 855 JSONL = 855 ids).
\end{itemize}

\subsection*{Caveats de calidad de datos (anotados)}
\begin{itemize}
  \item La búsqueda por alcaldía es \textbf{geo-radial / con match de texto}:
        un seed devuelve propiedades de zonas vecinas. Se mitiga con dedup por
        \codigo{id} y la unión de todas las alcaldías.
  \item El campo \codigo{municipality} lo captura el broker y \textbf{a veces es
        incorrecto} (ej. un anuncio con coords en CDMX etiquetado ``Morelia'').
        La señal confiable de ubicación es \codigo{\_geo} (lat/lng).
  \item \codigo{lastUpdate} es \textbf{última actualización}, no fecha de
        publicación pura (el listado no la expone). Se usa como proxy de
        ``reciente''.
\end{itemize}
